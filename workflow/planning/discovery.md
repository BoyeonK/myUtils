# Discovery

## 목적

사용자의 최초 요청과 현재 프로젝트 상태를 이해한다.

이 단계에서는 해결책을 확정하지 않는다.

---

## 수행할 작업

필요한 범위에서 다음을 조사한다.

- 사용자가 실제로 해결하려는 문제
- 현재 프로젝트에서 관련 기능이 존재하는지
- 관련 코드와 현재 동작
- 관련 테스트
- 기존 설계와 제약
- 기존에 내려진 관련 결정
- 유사하거나 중복되는 기능
- 변경 시 영향을 받을 수 있는 영역

Project Context를 확인하는 방법은 현재 프로젝트의 instructions와 repository 구조를 따른다.

앞선 단계나 이전 작업에서 이미 확인된 유효한 Project Context가 있다면 재사용할 수 있다.

---

## Project Context 탐색 범위

Project Context는 현재 요청을 이해하고 다음 단계의 판단에 필요한 최소 범위부터 확인한다.

관련 가능성이 있다는 이유만으로 repository 전체나 관련 문서 전체를 선제적으로 조사하지 않는다.

추가 정보가 실제 판단에 필요해졌을 때 탐색 범위를 확장한다.

이미 확인한 Project Context는 전제가 변경되었거나 사실 확인이 필요한 경우가 아니라면 불필요하게 다시 읽지 않는다.

---

## 정보 상태

Discovery에서 확인하거나 제안하는 내용은 Workflow의 공통 정보 상태를 따른다.

### Confirmed

사용자, 코드, 테스트 또는 프로젝트 자료에서 확인된 사실.

### Proposed

현재 상황에서 고려할 수 있는 AI의 제안.

### Open

아직 결정되지 않은 사항.

---

## 단계 경계

Discovery의 목적은 현재 문제와 Project Context를 이해하는 것이다.

조사 과정에서 해결 방향이나 설계 아이디어를 발견할 수 있지만,
이를 이 단계에서 확정하지 않는다.

필요하면 `Proposed` 또는 `Open`으로 남기고 이후 단계에서 다룬다.

---

## 기록

Discovery에서 이후 단계가 의존하는 핵심 Project Context를
`.workflow/tasks/<task-id>/status.md`에 기록한다.

필요에 따라 다음을 남긴다.

- 현재 Workflow 상태
- 확인된 핵심 Project Context
- 주요 제약과 기존 결정
- 영향을 받을 가능성이 있는 영역
- 남아 있는 Open Question
- 관련 artifact 또는 원본 자료의 위치

상세한 코드나 문서 내용을 복사하지 않는다.

세션이 바뀌더라도 이후 단계의 전제를 복원할 수 있는 최소 정보만 기록한다.

---

## 종료 조건

다음을 설명할 수 있으면 Discovery를 종료한다.

- 사용자가 해결하려는 문제가 무엇인가
- 현재 프로젝트의 관련 상태는 어떠한가
- 기존 제약과 관련 결정은 무엇인가
- 변경 시 영향을 받을 가능성이 있는 영역은 무엇인가
- 아직 무엇을 결정해야 하는가

핵심 Discovery 결과가 `status.md`에 반영되어 있어야 한다.

조건을 만족하면 Specification으로 이동한다.
